# 修正流程

在使用既有 harness 完成修改，或 SKILL.md 步驟 5 時讀本文件。

## 每一輪只處理一個根因

1. 執行統一入口，讀 exit code、finding 與該 check 的原始輸出。
2. 若有環境或設定錯誤，先處理它。必要工具未執行時無法據此判斷程式正確。
3. 選第一個尚未處理的根因，讀取 `source` 指向的程式與規則來源。
4. 寫一句可驗證假設，例如「domain 直接匯入 database；改由 constructor 接收介面後應不再出現 ARCH001」。
5. 做本次授權內的最小修正，跑對應 check；成功後再跑完整入口。
6. 更新下面的短紀錄。每次修改後的舊 pass 都失效。

```text
輪次: 1
入口: python3 tools/verify.py --config harness.json
exit code: 1
根因: ARCH001 / src/domain/order.py 依賴 database
修正: 注入既有 repository port
局部結果: pass
完整結果: 尚未執行
下一步: 跑完整入口
```

runner 的退出碼：`0` 全部通過、`1` 檢查失敗、`2` 設定或執行錯誤。
其他既有工具仍按自身文件解讀；非零都不能當成 pass。

## 收斂與停止

預設每個根因最多做 3 輪修正。若使用者指定不同預算，使用其預算。
連續 2 輪得到相同根因與相同證據時，先停止重複修改，補做一次有針對性的診斷。
若能找到新的可驗證原因且預算未用完，繼續；否則回報阻礙。
多個獨立根因分開計數，完成一個後接續處理其餘已授權工作。

| 情況 | 動作 |
| --- | --- |
| finding 指出程式違規 | 修正程式，再跑局部及完整驗證 |
| checker 誤報，有反例證明 | 修復 checker 並加入該反例，同時保留原違規 fixture |
| 缺少工具、權限、秘密或外部服務 | 完成可獨立進行的工作，列出缺少條件；必要 check 維持未通過 |
| 規則衝突或要新增例外，但沒有相應授權 | 提供具體衝突與最小選擇，向使用者確認 |
| 相同原因無法取得新證據，或達預算 | 保留變更、證據、未完成項及下一步；不要宣稱完成 |
| 全部必要 gate 在最新修改後通過 | 檢查 diff 並交付 |

修正以滿足原規則為目標。移除測試、縮小掃描範圍、忽略 exit code、延長例外效期，都需要自身的需求與授權依據。
不要把這些操作當成消除紅燈的方法。

## 恢復工作

長任務已有 plan 或進度檔時，把上述短紀錄存入既有位置。
恢復時先確認目前 diff，再讀最後一次入口、失敗與下一步；繼續尚未完成的根因。
紀錄只保存摘要與檔案位置，避免複製大量 log 或秘密。
